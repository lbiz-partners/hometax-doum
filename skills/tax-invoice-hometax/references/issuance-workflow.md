# 세금계산서 발급 화면 진행·복구

신규·수정 발급의 화면 조작 전에 읽는다. 현재 화면과 사용자 응답을 근거로 다음 한 단계만 진행한다. 사업장, 거래처, 금액 기준, 품목, 이번 거래 일자, 과세구분, 대금 수령 여부 중 이미 확인한 값은 유지하고 미확정 값만 묶어서 묻는다. 이전 거래의 일자를 이번 거래로 복사하지 않는다.

## 진입과 인증

- **신규 발급**은 전체메뉴 → 계산서·영수증·카드 → 전자(세금)계산서 발급 → 전자(세금)계산서 건별발급을 현재 화면에서 찾는다. 직접 주소가 메인으로 돌아오면 메뉴로 이동한다. 긴 메뉴명 검색이 0건이면 `전자세금계산서`처럼 짧은 검색어로 한 번 확인한다.
- **수정발급**은 신규 건별발급으로 이동하지 않는다. 원본 전자세금계산서 조회 → 현재 화면의 수정발급 진입 → 수정사유 확인 순서로 진행하고 `amend-types.md`를 읽는다. 이 문서의 알림·검산·중복 방지 규칙은 공통으로 적용하되 원본 값과 사유별 변경 항목을 대조한다.
- 로그인, 사업장 전환, 추가 인증을 구분한다. 공급자 사업장이 맞는지 확인한다. 인증은 사용자 본인이 진행하며 원래 탭과 인증 창을 유지한다. 인증 완료 응답 후 발급 양식이 실제 열렸는지 다시 읽는다. 로그인부터 반복하거나 인터뷰를 다시 시작하지 않는다.

## 저장 거래처 조회

1. 거래처 조회 팝업이 열리면 조회 조건을 확인하고 **조회 버튼을 실행**한다. **조회 전 0건은 거래처 없음이 아니다.**
2. 조회 후 사업자번호·상호로 정확한 행을 특정한다. 휴·폐업 표시를 확인하고 폐업 건은 진행하지 않는다. 이름이 비슷하거나 복수 후보면 사용자에게 구분 정보만 받는다.
3. 행 선택 후 하단 확인 또는 화면에 안내된 더블클릭으로 반영한다. 열린 알림을 처리한 뒤 원래 양식의 사업자번호·상호·성명·주소·이메일을 다시 읽어 의도한 거래처와 대조한다. 선택 행만 보고 반영 완료로 처리하지 않는다.
4. 조회를 실행해도 대상이 없으면 저장되지 않은 기존 거래일 수 있다. 신규 입력 경로로 전환하고 부족한 정보만 한 번에 받는다. 무한 조회·인터뷰 반복 금지.

## 알림과 빈칸

- `정상적인 사업자번호입니다`는 번호 검증 결과이며 상호·주소 자동입력이나 휴·폐업 확인 완료를 보장하지 않는다. 알림을 닫고 실제 필드를 다시 읽는다.
- 지원되는 브라우저 대화상자 기능으로 확인 알림을 처리한다. 도구가 응답하지 않으면 같은 호출을 반복하지 말고 현재 화면을 보존한 채 사용자에게 해당 알림의 확인 클릭만 요청한다. 응답 후 최신 화면을 읽고 이어간다. 알림을 우회하려고 새로고침하거나 작성 내용을 버리지 않는다.
- 번호 확인 후 상호·성명·주소 등이 비어 있으면 사업자등록증 또는 사용자 확인으로 채운다. 화면상 필수인 업태·종목도 함께 받는다. 자동입력을 기다리며 같은 조회를 반복하지 않는다. 필수 빈칸·불일치는 QA 확인필요/실패다.

## 일자·금액·영수/청구

- 이번 거래의 작성일자와 공급 사실을 사용자에게 확인한다. 화면에 `작성일자는 공급 연월일을 의미함`이라고 표시되면 상단 작성일자와 품목 행의 월·일을 대조한다. 품목 월이 상단 날짜에서 반영되는지 읽고, 별도 공급일자 입력칸을 찾느라 반복하지 않는다. 거래 사실과 맞지 않거나 복수 공급일이면 확인 후 진행한다.
- 공급가액인지 부가세 포함 합계인지 이미 받은 답을 적용한다. 합계로 받은 과세 건은 현재 화면의 품목별 계산 기능에 합계를 입력하고 계산 결과의 공급가액·세액을 확인한다. 적용 전후와 합계를 다시 읽는다. 원 단위 차이는 화면 계산·검증을 확인하며 임의 보정하지 않는다. 영세율·면세에 10% 계산을 적용하지 않는다.
- 사용자 금액과 입력값의 자릿수를 대조한다. 예: 공급가액 200만원을 20,000,000원으로 입력했다면 실패다.
- 대금을 받았으면 영수, 미수령이면 청구인지 확인한다. AI는 선택을 안내하고 **영수/청구 선택은 사용자 본인**이 한다. 선택 후 실제 상태를 다시 읽는다.

## 미리보기와 최종 확인

- **미리보기 열림은 검증 통과가 아니다.** 빈 양식도 미리보기가 열릴 수 있다. `pre-issue-checklist.md`의 모든 해당 항목을 현재 값으로 확인한다. 확인필요·실패가 하나라도 있으면 발급을 권하지 않는다.
- 본문과 미리보기 양쪽의 **발급하기는 사용자 본인**이 클릭한다. 인증도 본인이 진행한다. **발급보류는 저장 동작**이므로 테스트나 대기 버튼으로 누르지 않는다.
- 미리보기 내용을 원래 양식과 대조하고 확인 문구에 공급자·공급받는자, 문서 종류, 일자, 공급가액·세액·합계, 금액 기준, 영수/청구를 포함한다.

## 처리 지연과 중복 방지

- 사용자가 발급을 누른 뒤 처리 중이거나 승인번호가 안 보이면 **발급 버튼 재클릭 금지**. 시간이 지났다는 이유만으로 실패로 단정하지 않는다. 현재 처리 상태·오류 문구를 읽고 사용자에게 진행 상태를 알린다.
- 조회가 필요하면 현재 메뉴에서 발급 목록을 열고 같은 공급자 사업장, 발급/작성일 기준과 기간, 공급받는자, 문서 종류, 금액을 대조한다. 작성일 기준에는 원래 입력한 작성일, 발급일 기준에는 실제 발급 시도일이 포함되도록 한다. 오늘 날짜를 작성일로 대신하지 않는다. 날짜가 없으면 보존한 양식·사용자 답을 확인하고 없을 때만 묻는다. 조회를 실제 실행했는지 확인한다. **조회 전 0건·잘못된 필터·반영 지연은 미발급 증거가 아니다.**
- 발급완료와 승인번호 또는 일치하는 발급 내역을 확인해 완료를 보고한다. 원거래 미발급이 확정되기 전에는 재발급을 제안하지 않는다. 불확실하면 확인필요로 남기고 오류·처리 상태에 따른 공식 안내를 확인한다.
- 발급 완료, 이메일 전송 상태, 대금 입금 여부를 각각 구분한다. 이메일 미수신만으로 세금계산서를 다시 발급하지 않는다.
